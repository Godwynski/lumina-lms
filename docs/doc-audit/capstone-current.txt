INTRODUCTION
Project Context
The way information is managed continues to change as technology becomes more advanced, yet many school libraries still face challenges in organizing and maintaining their resources at STI College Alabang, the library serves a large number of students from different academic programs, each needing access to various books, references, and learning materials every day. Because of this high demand, the library needs a system that can efficiently track and manage all resources.
At present, the library still uses manual methods such as writing borrowed books in logbooks or recording them in spreadsheets. Librarians also check shelves manually to see if books are available. These methods take a lot of time and can lead to mistakes. Records may not always be updated right away, information can be misplaced, and handwriting may be difficult to read. Because of this, students sometimes have a hard time finding the books they need, and librarians struggle to keep accurate records.
This problem is not only seen in STI College Alabang but also in many schools that still use traditional library systems. As the number of students and books increases, it becomes harder to manage all transactions properly. Books may be returned late, misplaced, or even lost without proper tracking. Over time, this can lead to incorrect inventory records, which affects how the library operates.
To solve these problems, this study proposes a web-based library book reservation, borrowing, and inventory management system with QR-based scanning for STI College Alabang. The system is designed to make library transactions faster and easier. Students can reserve books online, while librarians can manage records through a single system. QR codes will be used to quickly identify books and process borrowing and returning.
With QR-based scanning, each book is given a unique code that can be scanned using a device. This makes the process faster and reduces human error. It also allows the system to update records in real time, helping ensure that the inventory is always accurate.
The system also aims to improve convenience for both students and librarians. Students will no longer need to manually search for book availability, as they can easily check and reserve materials through the system. Librarians, on the other hand, can spend less time on manual encoding and focus more on assisting students.
In addition, the system helps improve data safety and organization. Digital records are easier to store, update, and back up compared to manual records. It also helps reduce the risk of losing important information and ensures that only authorized users can access or modify data.
Lastly, the system can help the library make better decisions. With organized data, librarians can see which books are most used, which materials need updating, and how resources are being used overall. This helps improve the library’s services and better support student needs.


Purpose and Description
This project provides STI College Alabang with a streamlined digital library management system that replaces manual processes with efficient QR code scanning and online book reservations. Designed for reliability, the user-friendly platform centralizes library tasks into one accessible web interface, ensuring that data is managed effectively and operations remain consistent. By modernizing circulation and inventory tracking, the system enhances data security and provides a more organized, seamless experience for both students and Admin.

Scope and Limitations
Technology has changed the way libraries work, making it much faster to track books and share information compared to old paper methods. Instead of searching through boxes of cards, computers now let us check if a book is available in just a few seconds. This project follows that trend by bringing digital tools to the STI College Alabang library.
Scope of the Study
Super Admin
* Login Module
This module provides a secure and standardized entry point for library staff using Microsoft O365 authentication. It restricts access to administrative tools to ensure that only authorized personnel can manage library data.
* Dashboard Module
This module provides a centralized, high-level control panel that gives Super administrators a real-time overview of daily operations and system metrics. It displays critical data including daily visitor counts, registered users, total book inventory, and active loans, allowing for efficient resource monitoring. Additionally, the module features quick-access navigation shortcuts to core administrative features such as circulation desk, book inventory, user directories, visitor logs, audit logs, and analytics and showcases a visual gallery of the most recently cataloged library assets. 
* Inventory Module
This module allows the Super Administrator to manage the library's collection of books by automatically fetching details via ISBN lookup and manually finalizing records like Dewey Decimal numbers, categories, copy counts, and shelf locations. It also includes a Batch Catalog Operations panel featuring an Import Sheet tool for uploading spreadsheets via drag-and-drop, an ISBN Fallback text field for bulk sequential lookups and cover art retrieval, and an Export Data manager with fully customizable column selection to download the active catalog as a Spreadsheet, CSV, JSON Data, or Covers ZIP file. 
* Circulation Desk Module
This module automates the borrowing and returning process by utilizing QR-Code scanning technologies. By scanning student IDs and book codes, the system automatically links the borrower to the item, reducing manual data entry and transaction time. 
* Borrowing Logs Module
This module shows a simple, view-only list that lets the super administrator track when books are borrowed and returned. Limitation
* The system requires an active internet connection to synchronize data and operate its cloud-based features.
* System capacity and performance are restricted by the database size, serverless execution bounds, and storage limits of the chosen free-tier cloud infrastructure.
* Automated fetching of book data via ISBN can be supplemented manually when metadata is incomplete; accession numbers are auto-generated sequentially by the database (ACC-XXXXX), while Dewey Decimal classification can be retrieved via ISBN API lookup or manually specified.
* Authentication is exclusively tied to Microsoft 365 institutional accounts, which prevents access for outside researchers or users without an official school email.
* The QR-based automation heavily depends on functional device cameras and readable physical codes, meaning transactions will fail if the hardware is broken or the printed code is damaged.
* The searchable catalog focuses strictly on physically available local resources, exclusively managing physical book assets, meaning it does not integrate with enterprise-grade electronic research databases like EBSCO.
* The application is constrained by external API rate limits and real-time synchronization quotas, which may restrict the volume of requests processed during peak library hours.

Review of Related Literature
Global Shift Toward Digital Library Transformation
The rapid evolution of digital technologies has significantly impacted how libraries operate, leading to a shift in library services locally and internationally. Despite the widespread acknowledgment of this digital shift, there remains a substantial gap in understanding of how academic libraries are adapting, specifically in integrating digital innovations to enhance user access and engagement. In the study of Distanont et al (2024), there is a critical global trend toward integrating digital innovations to enhance user engagement. This shift is not merely about digitizing records but about strategic adaptation to a landscape where users expect seamless access. This is further supported by Wijaya et al (2025), which emphasizes that libraries relying on manual bookkeeping face inaccurate data recording and time-consuming searches, which hinder the efficiency of library services and reduce the interest of students.  As libraries, such as STI College Alabang, manage growing collections and student population, the integration of modern identification and tracking technologies has become essential for maintaining operational integrity and user satisfaction.
Institutional Security and Microsoft 365 Integration
A primary concern in digital transformation is the security of institutional data. Literature on Identity and Access Management (IAM) highlights that existing platforms, like Microsoft O365, provides enterprise-grade security, including Multi-Factor Authentication (MFA). In line with this, Kasahara and Shimayoshi (2022) provided a high-level technical precedent for the use of Microsoft 365 tenants to manage university students. The research highlights the necessity of Multi-Factor Authentication (MFA) and Azure Active Directory to prevent malicious software from compromising student accounts. By implementing M365 authentication, the present study aligns with global best practices that prioritize controls of user access behavior, ensuring that library services are restricted to verified students while offering a self-enrolling convenience that reduces administrative conflict (Kasahara & Shimayoshi, 2022).
QR-Based Scanning and Operational Efficiency
The integration of Quick Response (QR) codes represents an opportunity to modernize asset tracking. Paul and Naikar (2024) defined QR codes as powerful tools for instant access to catalog information and operational efficiency. Unlike traditional bookkeeping, QR codes can be scanned using mobile devices or low-cost scanners and QR technology allows for fast data retrieval at a minimal cost (Din & Fazla, 2021). This automation ensures that every transaction is instantly linked to the correct user profile, maintaining a precise digital borrowed history.
However, in practical application, as seen in the study of Mulya and Sari (2024), the transition from conventional systems to QR-web-based applications enables librarians to manage large quantities of data effectively. This technology minimizes manual effort and reduces data-entry errors by automating the link between the identity of the borrower and the library asset (Pebrian & Gunanto; 2025, Wijaya et al., 2025).
Centralized Web-Based Architectures and Real-Time Data
Modern Library Management Information Systems (MIS) are increasingly built on robust web frameworks, like JavaScript, Tailwind CSS, TypeScript, or PostgreSQL, to ensure structured and secure development (Rajee et al., 2022, Wijaya et al., 2025). The literature suggests that a module-based approach, which comprises registration and circulation among the university is the most effective way to meet the needs of diverse users (Abdullah et al., 2021). Furthermore, the inclusion of an audit log provides a transparent trail of all system modifications, which suggests that automated logs are essential for preventing unauthorized changes and ensuring the safety of institutional data.
A benefit identified in the study of Pebrian and Gunanto (2025) is the real-time synchronization of stock quantities. When a student submits a borrowing request using a web interface, the system updates in real-time, providing an up-to-date status that supports data-driven evaluation and strategic decision-making for administrators, such as librarians and even university principals.
Enhancing User Experience through Personalization and Visualization
Modern library users expect the same level of convenience found in e-commerce platforms. Beyond simple borrowing, advanced web applications are now incorporating data visualization and personalized recommendations to meet the evolving needs of students (Facunla & Encarnacion, 2024). Guided by Technological Acceptance Theory (TAT), researchers found that tailored web applications can achieve effectiveness rates as high as 97.48% when they focus on usability and reliability. This aligns with the Lumina project goal of providing a personalized student dashboard to help students track their own history and deadlines, thereby increasing their engagement with library resources.

Technical Background
Overview of current Technologies to be used in the system
The system is built upon a modern, high-performance tech stack designed for scalability, security, and a premium user experience. At its core, the application utilizes Next.js, a powerful React framework that enables server-side rendering and optimized routing, ensuring fast load times and seamless navigation. This foundation is reinforced by TypeScript, which provides a robust type system to catch errors early and maintain high code quality across the entire development lifecycle. The combination of these core technologies allows for a highly responsive and maintainable codebase that can adapt to evolving requirements.
For backend infrastructure, the system leverages Supabase, an open-source Backend-as-a-Service that provides a managed PostgreSQL database, integrated authentication, and real-time data synchronization. This allows the system to handle complex data relationships and user security with minimal overhead, utilizing Row-Level Security (RLS) to ensure data integrity at the database level. The backend is further supported by Node.js, providing a scalable runtime environment for executing server-side logic and managing asynchronous operations efficiently.
The user interface is crafted with a focus on aesthetics and accessibility, utilizing Tailwind CSS for rapid, utility-first styling and Radix UI for unstyled, accessible component primitives. Fluid animations and interactive transitions are powered by Framer Motion, while Lucide React provides a consistent and modern iconography set. Data visualization is handled by Recharts, offering clear and actionable insights through responsive charts. Together, these tools create a cohesive design system that feels premium, alive, and intuitive for every user.

Radix UI is an unstyled, accessible component library that provides the foundational building blocks for creating high-quality design systems. By offering "headless" components that handle complex logic such as focus management, keyboard navigation, and ARIA attributes it allows developers to focus entirely on custom styling. This ensures that the system's interactive elements are fully accessible and standards-compliant while maintaining a unique and premium visual identity.

Recharts
Recharts is a composable charting library built with React components, specifically designed for rendering data-rich analytics and statistics. It uses a declarative approach to define charts, making it easy to build complex visualizations like line graphs, bar charts, and pie charts that are both responsive and interactive. In the system dashboard, Recharts is used to translate raw library data into actionable visual insights for administrators and librarians.
Sonner
Sonner is an opinionated and lightweight toast component for React that provides customizable, non-intrusive notifications for user actions. It is used to deliver real-time feedback such as success messages after saving data or error alerts when a scan fails without disrupting the user's flow. Its clean design and smooth animations align perfectly with the system's aesthetic, providing a polished way to manage transient application states.
Supabase
Supabase is an open-source Backend-as-a-Service (BaaS) that provides the core infrastructure for the system, including a PostgreSQL database, user authentication, and real-time APIs. It simplifies backend development by offering a unified interface for data management and security, allowing the team to implement complex features like Row-Level Security (RLS) with ease. Supabase serves as the "source of truth" for all system data, ensuring reliability and high availability.
Tailwind CSS
Tailwind CSS is a utility-first CSS framework used for rapidly building and styling custom, responsive user interfaces. Instead of writing traditional CSS, it allows developers to apply styles directly within HTML or JSX using predefined utility classes, which promotes consistency and speed. This framework is essential for maintaining the system's high-density layout and ensuring that the design remains responsive across various device types
TypeScript
TypeScript is a strongly typed programming language that builds on JavaScript by adding static type definitions. It is used throughout the codebase to ensure better code quality, improve developer productivity, and eliminate entire classes of runtime bugs. By providing clear interfaces and type safety for both frontend and backend logic, TypeScript makes the system more robust and easier to refactor as it grows in complexity.
Vercel
Vercel is a cloud platform specifically tailored for Next.js workflows, used for deploying and hosting the web application. It provides a seamless CI/CD pipeline, automatically deploying changes from the repository and offering global edge network delivery for maximum performance. Vercel's infrastructure ensures that the system is always accessible, fast, and secure, with features like automatic SSL and serverless function scaling.
Zod
Zod is a TypeScript-first schema declaration and validation library used for ensuring the integrity of data inputs and API responses. It allows developers to define clear data schemas that are automatically synchronized with TypeScript types, providing both runtime validation and compile-time safety. In this system, Zod is used to validate form submissions, environment variables, and database records, preventing malformed data from causing system errors.

METHODOLOGY
This project uses the Iterative Development method to build and set up A Web-Based Library Book Reservation, Borrowing, and Inventory Management System with QR-Based Scanning for STI College Alabang. We chose this approach for one main reason: it allows us to build the system and write our research paper at the same time. Instead of waiting to finish all the paperwork before writing code, this method lets us work on small parts of both tasks together. This helps us make steady progress and ensures our written report always matches the real, working system. 
  ________________


Stage 1  Planning 
In this first step, we plan the main features we want to create for a specific part of the library system, such as the login page or the QR scanner. At the same time, we write down these initial plans and requirements directly into our project document.
Stage 2  Design
Next, we design how that specific part of the system will look and work. We map out the user screens and database layouts for that feature. As soon as the design is ready, we add these sketches and diagrams to our paper.
Stage 3  Implementation 
This is the step where we actually write the code and build the feature we just designed, like creating the book inventory table. Working this way allows us to draft the technical descriptions in our manuscript while the coding is fresh in our minds.
Stage 4 Testing 
Once the feature is coded, we test it carefully to make sure there are no errors. We check that the QR codes scan properly and that books can be borrowed without issues. All the test results and fixes are written straight into our report.
Stage 5  Evaluation 
In this final step of the cycle, we look at the tested feature to see what works and what needs to be fixed. Once this part is reviewed and finalized, we update our paper to match it perfectly, and then we start the cycle all over again for the next system feature.

Interviewer: Today, we are here for an interview about our research title: "A Web-Based Library Book Reservation, Borrowing, And Inventory Management System With Qr-Based Scanning For STI College Alabang." Are there any features you can suggest we add?
Interviewee: Do you have a set of questions prepared? First, is the design origin intended to be online or offline?
Interviewer: What we have in mind is to make it both online and offline. It can function offline so that when there's no internet, the system will still work. But when there is internet connection, it will sync to the cloud, similar to the concept of Microsoft 365. We designed it this way so that when recording data, since books have ISBN barcodes, we can simply scan them, and the title and author will automatically be fetched.
Interviewee: The first group I talked to had a Windows-based system, but your concept can indeed be a web-based system that works both online and offline. Okay, go ahead. What are your questions regarding the features?
Interviewer: We just want to ask if there are any specific features you'd like us to add? Also, our system is capable of generating...
Interviewee: My first question is, what are the basic requirements of a library system? Do you have an idea?
Interviewer: Borrowing, sir. We will allow that in the system.
Interviewee: Usually, it requires more than just borrowing. What modules make up the basic system of a library?
Interviewer: It will record the data of the books. But it's not just about recording.
Interviewee: Let's ask AI: "What are the basic modules or requirements of a library system based on standards used widely in universities abroad and here in the Philippines?" Also, we need to clarify is this library system intended for Senior High School (SHS) or the college level?
Interviewer: Actually, sir, it's intended for the whole school.
Interviewee: That's possible. There is a specific system structure used for Senior High, but we can confirm the appropriate standards with your school librarian.
Interviewer: I think a unified system is possible because we plan to use the students' school Microsoft accounts for the logins.
Interviewee: Usually, college and senior high school libraries are managed separately. When you go to a library, books are categorized by specific numbers—you don't just search for them randomly. They follow a classification system, like the Dewey Decimal System, where specific numbers correspond to specific subjects. Aside from the ISBN, there is a traditional coding system you must follow. An integrated library system, like Koha or Follett Destiny, can actually manage both levels. They handle this by using the same software but assigning different branch codes, allowing the librarian to see which book belongs to the high school wing and which to the college wing. You need to consider these library standards and perhaps look into what top universities use, such as enterprise-grade library platforms.
Interviewer: We also have an idea regarding the data. Requirements Documentation
This specific part defines the software features of the web-based system of Lumina: A Web-Based Library Book Reservation, Borrowing, and Inventory Management System with QR-Based Scanning for STI College Alabang. The requirements stated below are formulated based on the data gathered, standard operating procedure analysis, and key stakeholder consultations conducted with the library staff and administration of STI College Alabang, as well as particularly selected information based on the specific objectives of this study. The defined requirements below are expected to cater to the operational needs of STI College Alabang to enhance library transaction efficiency, inventory tracking accuracy, and asset security. The requirements below also describe how all the authorized users Super Administrators, Librarians, Student Assistants, and Students of STI College Alabang can interact with the system. 
4.1. Functional Requirements
4.1.1. Log In (Super Admin)
REQ001. The super admin shall be able to log in securely using Microsoft O365 institutional account credentials.
REQ002. The system shall restrict access to administrative tools to ensure that only authorized super administrative personnel can manage backend data.
4.1.2. Dashboard Module (Super Admin)
REQ003 . The super admin shall be able to view a real-time overview displaying metric summary counters for daily visitor traffic, registered users, total book inventory, and active loans.

REQ005. The super admin shall be able to view a visual gallery highlighting the most recently cataloged library assets on the main dashboard interface.

REQ008. The super admin shall be able to utilize a Batch Catalog Operations panel equipped with a drag-and-drop Import Sheet tool for uploading inventory spreadsheets.
REQ009. The super admin shall be able to utilize an ISBN Fallback text field for bulk sequential lookups and automatic cover art retrieval.

Specific Problem 
Super Admin 
* How to implement a secure login module using Microsoft O365 authentication for Super Administrator? 
In this module, users authenticate primarily through Microsoft Entra ID (O365 Azure OAuth), complemented by institutional email domain gating (@*.sti.edu.ph) and credential-based email/password authentication fallback.  
* How to develop an automated and detailed Inventory Module for library asset management? 
In this module, super administrator and staff can efficiently manage the library's collection of books by utilizing an automated ISBN fetch feature to retrieve book information. It provides the necessary interface for staff to manually input specific organizational metrics—such as the Dewey Decimal number, book categories, number of copies, and exact shelf locations—ensuring precise tracking and optimized physical resource organization. 
 
* How to implement an automated Circulation Desk Module for efficient borrowing and returning processes? 
 
In this module, the system utilizes QR-code scanning technologies to scan student IDs and book codes, automatically linking the borrower to the respective library item. This provides a streamlined workflow that drastically reduces manual data entry and minimizes transaction times for a more efficient counter service. 
 
* How to develop a comprehensive Borrowing Logs Module for tracking book transactions and statuses? 
 
In this module, super administrator and staff can monitor a centralized, view-only list tracking when books are borrowed and returned. It displays all key transaction details including borrower identification, book data, checkout dates, and due timelines while utilizing a search bar and status filters (All, Active, Returned, Overdue) to allow for quick record retrieval and efficient oversight of overdue items. 
 
* How to design and implement an Analytics Module with visual data dashboards for tracking system trends and performance? 
 
In this module, super administrator can filter historical operational data by specific timeframes such as 7 days, 30 days, or 1 year to monitor key metric summaries. Accessible to both Super Administrator and Librarian, visualizations include a Peak Visiting Hours bar chart, a Circulation Trends line graph, a Genre Popularity category distribution donut chart, and a High-Demand Catalog leaderboard, providing data-driven evaluation of library engagement and inventory performance. 
 
* How to establish a User Directory for user management and access control? 
 
In this module, Super Administrators and Librarians can manage user profiles and system access levels across all roles (students, student assistants, staff, and administrators). This ensures a secure database where library services are restricted to authorized individuals, allowing for efficient membership tracking and data protection. 
 
* How to implement an Attendance Logs Module for monitoring and tracking student traffic? 
 
In this module, library staff (Super Administrator, Librarian, and Student Assistants with delegated attendance permission) can monitor daily library usage by scanning student library cards to track entry and exit events, while students monitor personal attendance history. The system displays a complete, real-time list of checked-in and checked-out individuals alongside exact timestamps, providing a streamlined process for recording and managing daily student traffic. 
 
* How to develop a comprehensive Setting and Policies Module for system rule configuration and operational maintenance? 
 
In this module, super administrator can manage library rules and configurations through dedicated setup views to define circulation limits, program tracks, book categories, and announcements. Operational rules, circulation limits, categories, and announcements are shared between Super Administrator and Librarian, while backend lifecycle maintenance tools (annual account reset, automated maintenance dispatch, and test email execution) are exclusive to Super Administrator. 
 
* How to implement a secure Audit Logs Module for comprehensive activity tracking and system accountability? 
 
In this module, a robust security tracking system records all system modifications and user activities in a detailed data table featuring timestamps, user identities, action types, and technical difference logs. Super administrators can efficiently navigate large datasets using a real-time search bar, specialized dropdown filters, and live data refreshes, while utilizing an export CSV feature to download historical logs for deeper security compliance and data analysis. 
 
* How to design and implement a dynamic Notification Module for real-time system alerts and updates? 
 
In this module, super administrator are instantly alerted to critical system events and updates via a quick drop-down panel accessible from the system header. It provides a dedicated notifications page equipped with quick filter tabs and a targeted search bar, allowing staff to efficiently manage, find, and respond to specific alerts for enhanced situational awareness. 
 
* How to implement a view-only My Profile Module for secure account detail verification? 
 
In this module, logged-in users can view a secure, centralized overview of their personal account details. It displays critical identity and contact information including the user's full name, system ID, official email, contact number, residential address, account status, membership role, and security status ensuring a straightforward way for individuals to verify their registered profile data while allowing users to upload and crop their custom profile avatar photo.

Design of Software, System, Product, and/or Processes
In designing our software, system, and process, we utilized structured architectural and design approaches to create a secure, efficient, and user-centered system. The system follows a layered architecture consisting of the Presentation, Process/Logic, Database Client, and Database Core layers, ensuring clear separation of responsibilities and maintainability. Database design applies Third Normal Form (3NF) to minimize redundancy and maintain data integrity, while ACID transactions, row-level locking, advisory locks, and database triggers support reliable and concurrent library operations. Security was incorporated through authentication, role-based access control (RBAC), input validation using Zod, Row Level Security (RLS), restricted database procedures, and comprehensive audit logging. The system also applies ISO/IEC 25010 quality attributes, focusing on functional suitability, performance efficiency, compatibility, usability, reliability, security, maintainability, and portability. Integrating these architectural, database, security, and quality design practices resulted in a robust, scalable, and user-friendly library management product.

Testing
In this part, the proponents present the testing activities conducted for Lumina: A Web-Based Library Book Reservation, Borrowing, and Inventory Management System with QR-Based Scanning for STI College Alabang. Testing focuses on verifying whether the developed modules and functions operate according to their intended requirements. The system follows the Iterative Development method, where each feature is tested after implementation to identify errors and necessary improvements. The testing includes Microsoft O365 authentication, book searching and reservation, QR-based scanning, borrowing and returning, attendance monitoring, inventory management, notifications, and administrative functions, with the results used to improve the system in the next development cycle. To establish empirical software quality, the system was verified against an automated Vitest test suite of 51 test files and 1,017 automated tests (100% pass rate) and evaluated against the eight ISO/IEC 25010 product quality characteristics (Functional Suitability, Performance Efficiency, Compatibility, Usability, Reliability, Security, Maintainability, Portability).
Description of Prototype
The prototype is a web-based library management system designed to provide students and library personnel with a centralized platform for accessing and managing library services. It includes features such as book searching and reservation, borrowing and returning, inventory management, attendance monitoring, notifications, and user profile management. The system uses Next.js, TypeScript, Supabase, Tailwind CSS, and HTML5-QRCode for client-side camera scanning, alongside qrcode and sharp for server-side generation and rasterization of digital library cards and copy QR codes. Overall, the prototype is designed to improve the efficiency of library transactions, organize book records, and provide convenient access to library services for students and library personnel.

________________


Lumina, a library book reservation, borrowing, and inventory management system, addresses crucial aspects of academic administration in STI College Alabang, ensuring that educational institutions operate efficiently while meeting the needs of the faculty and students. This capstone project aims to explore the challenges and solutions in creating optimized tracking that balance book availability, borrowing queues, inventory counts, and conflict resolutions.
The study also evaluates QR-based scanning integration to prevent manual data entry errors while ensuring a balanced distribution of library resources.
By leveraging web hosting and securing a dedicated domain, the project aims to establish a widely accessible and secure platform for day-to-day operations. The adoption of a web-based application framework aligns with institution standards, providing a polished and professional interface for all users.
The primary objective is to offer a system that supports strategic tasks, improves utilization, enhances student learning experience, and addresses the academic needs of students.


CONCLUSION
The development and implementation of Lumina directly addresses the longstanding inefficiencies associated with manual library operations at STI College Alabang. By replacing time-consuming paper logbooks and manual shelf checks with a centralized, web-based platform, the project unifies book reservation, borrowing, circulation, and inventory auditing into a cohesive digital ecosystem.
Through the integration of QR-based scanning technologies, Microsoft O365 enterprise authentication, and a flexible iterative development methodology, Lumina ensures real-time data accuracy, minimizes administrative wait times, and safeguards institutional records. The modular system design fosters an intuitive, user-centric environment that simplifies daily tasks for administrators, librarians, student assistants, and students alike.

Ultimately, transitioning from traditional record-keeping to a modern, cloud-based digital framework resolves immediate operational bottlenecks while laying a scalable, future-ready foundation. This transformation directly supports STI College Alabang's broader commitment to academic excellence, data integrity, and digital innovation in library management.
Recommendation
The researchers conducted a complete evaluation of the system and identified advanced areas for system expansion, specifically AI-Driven Predictive Shelf-Life and Condition Forecasting, Automated Data-Anonymized CSV/JSON Audit Exporters for Accreditation, and Offline Queueing for Mobile QR Scanning . 
________________
The proponents propose the following recommendation: 
1.AI-Driven Predictive Shelf-Life and Condition Forecasting  
The integration of a machine learning regression model within the management information system (MIS) will optimize physical asset preservation. By tracking how often a specific physical book is circulated, its age, and historical damage logs, the system can flag textbooks that are at high risk of structural wear, allowing librarians to proactively plan for repairs, rebinding, or replacements before the material becomes unusable. 
2. Automated Institutional Accreditation Metric Transformations for CHEd and PAASCU Compliance  
Implementing an automated compliance module within the super-admin panel will greatly simplify institutional evaluation processes. Expanding upon existing CSV, JSON, and XLSX export capabilities, the system provides automated accreditation metric transformations—such as student-to-book ratio calculations, departmental retention indices, and automated PII scrubbing for CHEd and institutional accreditation reporting—without compromising student privacy or data integrity controls. 
3. Queueing for Mobile QR Scanning. 
Give librarians and student assistants who perform inventories in remote areas of the library or have poor internet connectivity offline access so they can continue scanning book QR codes; once a stable internet link is established, the scanned data and transaction logs will be automatically synchronized with the Supabase database.

USERS GUIDE
This guide provides instructions for students and library personnel on how to navigate and efficiently use the Lumina system. The system is designed to simplify library book reservation, borrowing, returning, inventory management, and attendance monitoring through a centralized web-based platform.
Lumina uses Microsoft 365 authentication for secure user login and provides role-based access to features intended for students and authorized library personnel.
System Requirements
* A device with internet access such as a PC, laptop, or smartphone.
* A valid STI Microsoft 365 account.
* A compatible web browser such as Microsoft Edge, Google Chrome, or Mozilla Firefox.
* An active internet connection.
1. Logging Into the System
1.1 Launch the System
Open a compatible web browser and navigate to the Lumina system website.
1.2 Microsoft 365 Login
On the login page, select Sign in with Microsoft (or use Quick Demo Access buttons for evaluation logins).
1.3 Enter Credentials
Enter the user's STI Microsoft 365 account credentials and complete the required authentication process.
1.4 Role-Based Access
After successful login, the system displays the dashboard and features according to the user's assigned role.
2. User Roles and Features (Student, Student Assistant, Librarian, Super Administrator)
A. Students
Students use Lumina to search for books, make reservations, monitor borrowed books, and view their library information.
Key Features
* View the Student Dashboard.
* Search and browse available books.
* View book details.
* Reserve available books.
* Track loan return deadlines and due soon reminders.
* View active borrowed books.
* View reservations.
* View borrowing history.
* Access the digital library card.
* Export the library card.
* View frequently asked questions.
* Manage profile information.
How To:
Search for a Book:
1. Navigate to the Catalog (/student-catalog for students, /inventory for staff).
2. Enter the book title, author, or other available search information.
3. Select the desired book.
4. Review the book details and availability.
Reserve a Book:
1. Open the Catalog.
2. Select an available book.
3. Click "Reserve for Pickup" (or "Reserve to Borrow" for waitlisted titles). The reservation is placed immediately upon click with a toast notification.
4. Confirm the reservation.
View Active Borrowed Books:
1. Open the Student Dashboard.
2. Locate the Current Borrows section.
3. Review the currently borrowed books and their corresponding information.
View Borrowing History:
1. Navigate to My Borrowing (/history for students, /history?view=logs for staff).
2. Review previously borrowed and returned books.
B. Library Personnel / Administrator
Library personnel are responsible for managing library resources, book circulation, users, inventory, and system settings.
Key Features
* Manage library books and assets.
* Add and edit book records.
* Monitor book statuses.
* Generate and print QR codes.
* Process book checkouts.
* Process book returns.
* Scan QR codes.
* Manage reservations.
* Monitor borrowing records.
* Manage users.
* Configure library policies.
* Manage book categories and programs.
* Manage announcements.
How To:
Add a Book:
1. Navigate to Inventory (/inventory) for catalog tasks, or Dashboard (/dashboard) for staff metrics.
2. Select Add Item.
3. Enter the required book information.
4. Use the automated ISBN lookup bar or enter book details, then click "Save to Catalog".
Edit a Book:
1. Open Inventory (/inventory) to view catalog cards.
2. Select the desired book or asset.
3. Click the edit icon (pencil) in the modal header, update metadata, and click "Save Changes".
4. Update the required information.
5. Save the changes.
Generate or Print a QR Code:
1. Open the book or asset record.
2. Select Print QR.
3. Review the generated QR code.
4. Click "Print QR" beside the physical copy row, review the code in the "Print QR Label" modal, and click "Print Label".
3. Circulation Desk Functions
The Circulation Desk is used by authorized library personnel to process book borrowing and returning transactions.
A. Checking Out a Book
1. Navigate to the Circulation Desk.
2. Select Checkout.
3. Launch the QR scanner.
4. Scan the student's library card or required identification.
5. Scan the QR code of the book.
6. Review the transaction details.
7. Follow the 3-step wizard (Identify Student -> Scan Resource -> Review) and click "Confirm Checkout" to finalize the loan.
B. Returning a Book
1. Navigate to the Circulation Desk.
2. Select Return.
3. Launch the QR scanner.
4. Scan the book's QR code.
5. Review the borrowing information.
6. Follow the 2-step wizard (Identify Resource -> Review) and click "Confirm Return" to finalize the transaction.
C. Resetting the Scanner
If a scanning transaction needs to be cleared, select Reset before starting a new transaction, or use the camera Stop and camera-switch viewport controls.
4. Managing Inventory
The inventory management functions allow authorized library personnel to monitor and maintain library book records.
Key Functions
* Add new library assets.
* Edit existing asset information.
* Monitor book status.
* Assign book categories.
* Generate QR codes.
* Update inventory records.
How To:
1. Navigate to Inventory (/inventory) for catalog tasks, or Dashboard (/dashboard) for staff metrics.
2. Select the appropriate inventory function.
3. Search for the required book or asset.
4. Add or update the necessary information.
5. Save the changes.
5. Managing Reservations
Library personnel can monitor and manage student book reservations.
How To:
1. Access the appropriate reservation or circulation section.
2. Review the list of active reservations.
3. Check the student's reservation information.
4. Verify the corresponding book.
5. Monitor reservation queues within the Inventory book detail modal (ReservationQueuePanel) and fulfill ready holds at the Circulation Desk during checkout.
6. Borrow History
The Borrow History section allows users to review borrowing transactions.
Students
Students can view their previous borrowing records, including books that have already been returned.
Library Personnel
Authorized personnel can review borrowing transactions to monitor library circulation and maintain accurate records.
7. User Directory
The User Directory allows authorized library personnel to manage registered users.
Key Functions
* View registered users.
* Search for users.
* Review user information.
* Manage user records across role tabs, approve card applications, execute bulk re-activations, and configure delegated permissions for Student Assistants.
8. System Settings and Policies
The Settings section allows authorized library personnel to configure library policies and system information.
________________
Available Settings
* Borrowing window.
* Maximum books allowed per student.
* Circulation durations (14-day loan period, 5-book limit, 7-day hold window) without monetary fine policies.
* Reservation shelf life.
* Queue slot limit.
* Programs.
* Book categories.
* Library announcements.
How To:
1. Navigate to Settings.
2. Select the policy or configuration that needs to be updated.
3. Enter the required information.
4. Review the changes.
5. Click "Review Changes" on the floating bar, enter a mandatory Audit Protocol Reason (minimum 10 characters) in PolicyCommitModal, and click "Confirm & Commit".
9. Common Functions
A. Reporting a Missing Book
Students can report a book that cannot be located in the library.
1. Navigate to the Catalog (/student-catalog for students, /inventory for staff).
2. Search for the missing book.
3. Open the book details.
4. Review catalog status (reporting missing books is not a student self-service feature; contact staff directly).
5. Submit the report.
B. Viewing the Library Card
1. Open the Student Dashboard.
2. Locate the Library Card section.
3. View the digital library card.
4. Use the Front/Back flip toggle to inspect card details, click the QR code to enlarge for scanner kiosks, or select Export to download a high-resolution PNG image.
C. Viewing FAQs
1. Open the Student Dashboard.
2. Locate the inline Support & FAQs section on the dashboard.
3. Select the question related to the user's concern.
4. Review the provided information.
10. Updating Personal Information
Users can access their profile to review or update available personal information.
1. Navigate to Profile.
2. Review the displayed information.
3. Note that personal records are read-only and synchronized from institutional data; the only permitted update is uploading and cropping an avatar photo via Avatar Manager.
4. Save the changes.

11. Logging Out
To securely exit Lumina:
1. Click the user's profile icon.
2. Select "Log out" with a space, and confirm the action in the prompt dialog by clicking "Log out".
3. The system will end the current session.
Users should always log out after using Lumina on shared or public computers.
12. Troubleshooting and Support
Issue
	Suggested Solution
	Unable to log in
	Check Microsoft Entra ID credentials; for "Account Pending Approval" await librarian review; for suspended accounts contact the Super Administrator.
	Cannot access a feature
	Check whether the feature is available for the user's assigned role.
	Book cannot be reserved
	Check book availability or whether the student has reached the maximum reservation limit (3 books).
	QR code cannot be scanned
	Ensure the QR code is positioned in front of the camera, or click "Retry Camera" or switch to manual ID/barcode input.
	Book information is incorrect
	Report the issue to authorized library personnel.
	Borrowing or returning transaction cannot be completed
	Review the transaction details and try the process again.
	System is not loading
	Check the internet connection and refresh the browser.
	

For unresolved issues, users should contact the authorized library personnel or system administrator.
