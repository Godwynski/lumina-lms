[p207] Introduction
[p208] Project Context
[p209] The way information is managed continues to change as technology becomes more advanced, yet many school libraries still face challenges in organizing and maintaining their resources at STI College Alabang, the library serves a large number of Patrons, including students from different academic programs and faculty, each needing access to various books, references, and learning materials every day. Because of this high demand, the library needs a system that can efficiently track and manage all resources.
[p211] At present, the library still uses manual methods such as writing borrowed books in logbooks or recording them in spreadsheets. Librarians also check shelves manually to see if books are available. These methods take a lot of time and can lead to mistakes. Records may not always be updated right away, information can be misplaced, and handwriting may be difficult to read. Because of this, Patrons sometimes have a hard time finding the books they need, and librarians struggle to keep accurate records.
[p213] This problem is not only seen in STI College Alabang but also in many schools that still use traditional library systems. As the number of Patrons and books increases, it becomes harder to manage all transactions properly. Books may be returned late, misplaced, or even lost without proper tracking. Over time, this can lead to incorrect inventory records, which affects how the library operates.
[p215] To solve these problems, this study proposes a web-based library book reservation, borrowing, and inventory management system with QR-based scanning for STI College Alabang. The system is designed to make library transactions faster and easier. Patrons can reserve books online, while librarians can manage records through a single system. QR codes will be used to quickly identify books and process borrowing and returning.
[p217] With QR-based scanning, each physical book copy is given a unique code that can be scanned using a device. This makes the process faster and reduces human error. It also allows the system to update records in real time, helping ensure that the inventory is always accurate.
[p219] The system also aims to improve convenience for both Patrons and librarians. Patrons will no longer need to manually search for book availability, as they can easily check and reserve materials through the system. Librarians, on the other hand, can spend less time on manual encoding and focus more on assisting Patrons.
[p221] In addition, the system helps improve data safety and organization. Digital records are easier to store, update, and back up compared to manual records. It also helps reduce the risk of losing important information and ensures that only authorized users can access or modify data.
[p223] Lastly, the system can help the library make better decisions. With organized data, librarians can see which books are most used, which materials need updating, and how resources are being used overall. This helps improve the library’s services and better support Patron needs.
[p225] Purpose and Description
[p226] This project provides STI College Alabang with a streamlined digital library management system that replaces manual processes with efficient QR code scanning and online book reservations. Designed for reliability, the user-friendly platform centralizes library tasks into one accessible web interface, ensuring that data is managed effectively and operations remain consistent. By modernizing circulation and inventory tracking, the system enhances data security and provides a more organized, seamless experience for both Patrons and library personnel. Library Staff refers to student assistants; Patrons include students and faculty.
[p228] Statement of the Problem
[p229] General Problem
[p230] The primary challenge of this research is to design, develop, and implement a comprehensive, web-based library management ecosystem for STI College Alabang that replaces manual or fragmented processes with a unified digital framework. Specifically, the problem centers on how to effectively integrate Microsoft O365 authentication for secure institutional access and QR-based scanning technology for efficient asset tracking, while simultaneously providing a unified system supporting automatic reservations, staff-processed borrowing and returns, overdue fine recording and settlement, and inventory management for Patrons (students and faculty) and library administrators.

[p527] Limitations
[p528] The system requires an active internet connection to synchronize data and operate its cloud-based features.
[p529] System capacity and performance are restricted by the database size, serverless execution bounds, and storage limits of the chosen free-tier cloud infrastructure.
[p530] Automated fetching of book data via ISBN can be supplemented manually when metadata is incomplete; accession numbers are auto-generated sequentially by the database (ACC-XXXXX), while Dewey Decimal classification can be retrieved via ISBN API lookup or manually specified.
[p531] Authentication is exclusively tied to Microsoft 365 institutional accounts, which prevents access for outside researchers or users without an official school email.
[p532] The QR-based automation supports optional camera or handheld scanning and typed identifiers; if a camera is unavailable or a printed code is damaged, staff can enter the card number, student ID, or copy accession number manually.
[p533] The searchable catalog focuses strictly on the library's physical book collection (including titles with copies on loan), meaning it does not integrate with enterprise-grade electronic research databases like EBSCO.
[p534] The application is constrained by external API rate limits and real-time synchronization quotas, which may restrict the volume of requests processed during peak library hours.

[p538] Global shift toward digital library transformation
[p539] The rapid evolution of digital technologies has significantly impacted how libraries operate, leading to a shift in library services locally and internationally. Despite the widespread acknowledgment of this digital shift, there remains a substantial gap in understanding of how academic libraries are adapting, specifically in integrating digital innovations to enhance user access and engagement. [p584] METHODOLOGY
[p585] This project uses the Iterative Development method to build and set up A Web-Based Library Book Reservation, Borrowing, and Inventory Management System with QR-Based Scanning for STI College Alabang. We chose this approach for one main reason: it allows us to build the system and write our research paper at the same time. Instead of waiting to finish all the paperwork before writing code, this method lets us work on small parts of both tasks together. This helps us make steady progress and ensures our written report always matches the real, working system
[p586] Stage 1: Planning
[p587] In this first step, we plan the main features we want to create for a specific part of the library system, such as the login page or the QR scanner. At the same time, we write down these initial plans and requirements directly into our project document.
[p588] Stage 2: Design
[p589] Next, we design how that specific part of the system will look and work. We map out the user screens and database layouts for that feature. As soon as the design is ready, we add these sketches and diagrams to our paper.
[p590] Stage 3: Implementation
[p591] This is the step where we actually write the code and build the feature we just designed, like creating the book inventory table. Working this way allows us to draft the technical descriptions in our manuscript while the coding is fresh in our minds.
[p592] Stage 4: Testing
[p593] Once the feature is coded, we test it carefully to make sure there are no errors. We check that the QR codes scan properly and that books can be borrowed without issues. All the test results and fixes are written straight into our report.
[p594] Stage 5: Deployment
[p595] In this step, we release the tested and verified feature into the live environment so that library users and administrators can start using it in practice. Any initial deployment steps or rollout notes are documented directly in our project records.
[p596] Stage 6: Evaluation
[p597] In this final step of the cycle, we look at the deployed feature to see what works and what needs to be fixed. Once this part is reviewed and finalized, we update our paper to match it perfectly, and then we start the cycle all over again for the next system feature.

The backend is further supported by Node.js 24, providing a scalable runtime environment for executing server-side logic and managing asynchronous operations efficiently.

[p716] This specific part defines the software features of the web-based system of Lumina: A Web-Based Library Book Reservation, Borrowing, and Inventory Management System with QR-Based Scanning for STI College Alabang. The requirements stated below are formulated based on the data gathered, standard operating procedure analysis, and key stakeholder consultations conducted with the library staff and administration of STI College Alabang, as well as particularly selected information based on the specific objectives of this study. [p718] 4.1. Functional Requirements
[p719] 4.1.1. Log In (Super Administrator)
[p720] REQ001. The Super Administrator shall be able to log in securely using Microsoft O365 institutional account credentials.
[p721] REQ002. The system shall restrict administrative tools according to each user's role, account status, and granted permissions.
[p722] 4.1.2. Dashboard Module (Super Administrator)
[p723] REQ003. The Super Administrator shall be able to view a real-time overview displaying metric summary counters for Today's Visitors, Active Borrows, Inventory (physical copies), and total users.
[p724] REQ004. The Super Administrator shall be able to view an Action Center (card applications, overdue borrows, ready holds) and live activity feed, while accessing Circulation Desk, Inventory, User Directory, Attendance Logs, Audit Logs, and Analytics via the sidebar.
[p725] REQ005. The Super Administrator shall be able to view recently cataloged books and their Library Card, and use Catalog to search (title, author, ISBN), filter/sort, check copies, and reserve or join a waitlist.
[p726] 4.1.3. Inventory (Super Administrator)
[p727] REQ006. The Super Administrator shall be able to automatically fetch book metadata (title, author, cover, and Dewey Decimal when available) via ISBN lookup (Google Books/Open Library).
[p728] REQ007. The Super Administrator shall be able to enter missing Dewey Decimal numbers, categories, copies, and shelf locations; book details provide per-copy acquisition/disposal, auto accession numbers, and QR labels.
[p729] REQ008. The Super Administrator shall be able to utilize a Batch Catalog Operations panel equipped with a drag-and-drop Import Sheet tool for uploading inventory spreadsheets.
[p730] REQ009. The Super Administrator shall be able to run background batch ISBN imports (up to 500 books) with automatic cover retrieval.
[p731] REQ010. The Super Administrator shall be able to export active catalog data with custom column selections into Spreadsheet, CSV, JSON Data, or Covers ZIP file formats.
[p732] 4.1.4. Circulation Desk (Super Administrator)
[p733] REQ011. The Super Administrator shall be able to scan or type Patron card and copy QR/accession IDs for checkout, and copy ID only for return (camera optional).
[p734] REQ012. The system shall require checkout confirmation, block self-checkout, and block overdue/lost/unpaid-fine loans unless a Librarian or Super Administrator overrides with a recorded reason.
[p735] 4.1.5. Borrowing Logs (Super Administrator)

[p866] Design of Software, System, Product, and/or Processes
[p867] In designing our software, system, and process, we utilized structured architectural and design approaches to create a secure, efficient, and user-centered system. The system follows a layered architecture consisting of the Presentation, Process/Logic, Database Client, and Database Core layers, ensuring clear separation of responsibilities and maintainability. Database design applies Third Normal Form (3NF) to minimize redundancy and maintain data integrity, while ACID transactions, row-level locking, advisory locks, and database triggers support reliable and concurrent library operations. Security was incorporated through authentication, role-based access control (RBAC), input validation using Zod, Row Level Security (RLS), restricted database procedures, and audit logging of key administrative actions. The system also applies ISO/IEC 25010 quality attributes, focusing on functional suitability, performance efficiency, compatibility, usability, reliability, security, maintainability, and portability. Integrating these architectural, database, security, and quality design practices resulted in a robust, scalable, and user-friendly library management product.

[p870] RESULTS AND DISCUSSION
[p871] Testing
[p872] In this part, the proponents present the testing activities conducted for Lumina: A Web-Based Library Book Reservation, Borrowing, and Inventory Management System with QR-Based Scanning for STI College Alabang. Testing focuses on verifying whether the developed modules and functions operate according to their intended requirements. The system follows the Iterative Development method, where each feature is tested after implementation to identify errors and necessary improvements. The testing includes Microsoft O365 authentication, book searching and reservation, QR-based scanning, borrowing, returning and fine settlement, attendance monitoring, inventory management, notifications, Report Builder, and administrative permissions, with the results used to improve the system in the next development cycle.
[p874] Description of Prototype
[p875] The prototype is a web-based library management system designed to provide Patrons and library personnel with a centralized platform for accessing and managing library services. It includes features such as book searching and reservation, borrowing and returning, fines and in-person settlement, Report Builder, inventory management, attendance monitoring, notifications, and user profile management. The system uses Next.js, TypeScript, Supabase, Tailwind CSS, and HTML5-QRCode for client-side camera scanning, alongside qrcode and sharp for server-side generation and rasterization of digital library cards and copy QR codes. Overall, the prototype is designed to improve the efficiency of library transactions, organize book records, and provide convenient access to library services for Patrons and library personnel.
[p877] Implementation Plan
[p878] The implementation of  A Web-Based Library Book Reservation, Borrowing, and Inventory Management System with QR-Based Scanning for STI College Alabang resulted in a centralized platform that supports book searching, reservations, borrowing and returning, inventory management, and attendance monitoring. Patrons can search and reserve books, view borrowing history and due dates, check attendance records, receive notifications, and access their profiles. Library personnel can manage book records and transactions using QR-based scanning, while administrators can manage inventory, borrowing logs, analytics and Report Builder, users, System Policies, and audit logs. Overall, the implemented features provide an organized digital platform that supports library operations, improves access to information, and reduces reliance on manual recording
[p879] Implementation Results
[p880] The implementation of  A Web-Based Library Book Reservation, Borrowing, and Inventory Management System with QR-Based Scanning for STI College Alabang resulted in a functional system that integrates the major library processes into one centralized web-based platform. The implemented modules allow Patrons to browse available books, reserve books for staff checkout, view borrowing history, and review profile details and manage their photo, while administrators can manage book records, monitor inventory, process borrowing and returns, and manage user transactions. The QR-based scanning feature was also implemented to support faster and more accurate identification of books and borrowing transactions. Overall, the implementation results demonstrate that the developed system successfully addresses the identified limitations of the existing manual processes by providing a more organized, accessible, and efficient approach to library management.
[p882] ConclusionThe development and implementation of Lumina directly addresses the longstanding inefficiencies associated with manual library operations at STI College Alabang. By replacing time-consuming paper logbooks and manual shelf checks with a centralized, web-based platform, the project unifies book reservation, borrowing, circulation, and inventory auditing into a cohesive digital ecosystem.
[p883] Through the integration of QR-based scanning technologies, Microsoft O365 enterprise authentication, and a flexible iterative development methodology, Lumina ensures real-time data accuracy, minimizes administrative wait times, and safeguards institutional records. The modular system design fosters an intuitive, user-centric environment that simplifies daily tasks for administrators, librarians, Library Staff, and Patrons alike.Ultimately, transitioning from traditional record-keeping to a modern, cloud-based digital framework resolves immediate operational bottlenecks while laying a scalable, future-ready foundation. This transformation directly supports STI College Alabang's broader commitment to academic excellence, data integrity, and digital innovation in library management.
[p885] Recommendation
[p886] The researchers conducted a complete evaluation of the system and identified advanced areas for system expansion, specifically AI-Driven Predictive Shelf-Life and Condition Forecasting, Automated Institutional Accreditation Metric Transformations for CHEd and PAASCU Compliance, and Offline Queueing for Mobile QR Scanning.
[p888] The proponents propose the following recommendation:
[p889] 1.AI-Driven Predictive Shelf-Life and Condition Forecasting  The integration of a machine learning regression model within the management information system (MIS) will optimize physical asset preservation. By tracking how often a specific physical book is circulated, its age, and historical damage logs, the system can flag textbooks that are at high risk of structural wear, allowing librarians to proactively plan for repairs, rebinding, or replacements before the material becomes unusable.
[p890] 2. Automated Institutional Accreditation Metric Transformations for CHEd and PAASCU Compliance
[p891] Implementing an automated compliance module within the super-admin panel will greatly simplify institutional evaluation processes. Expanding upon existing CSV, JSON, and XLSX export capabilities, the system could provide automated accreditation metric transformations such as Patron-to-book ratio calculations, departmental retention indices, and automated PII scrubbing for CHEd and institutional accreditation reporting without compromising Patron privacy or data integrity controls.
[p892] 3. Queueing for Mobile QR Scanning.
[p893] Give librarians and Library Staff who perform inventories in remote areas of the library or have poor internet connectivity offline access so they can continue scanning book QR codes; once a stable internet link is established, the scanned data and transaction logs will be automatically synchronized with the Supabase database.

[p1111] APPENDIX E. USER’S GUIDE
[p1112] USERS GUIDE
[p1113] This guide provides instructions for Patrons and library personnel on how to navigate and efficiently use the Lumina system. The system is designed to simplify library book reservation, borrowing, returning, inventory management, and attendance monitoring through a centralized web-based platform.
[p1114] Lumina uses Microsoft 365 authentication for secure user login and provides role-based access to features intended for Patrons and authorized library personnel.
[p1116] System Requirements
[p1117] A device with internet access such as a PC, laptop, or smartphone.
[p1118] A valid STI Microsoft 365 account.
[p1119] A compatible web browser such as Microsoft Edge, Google Chrome, or Mozilla Firefox.
[p1120] An active internet connection.
[p1121] 1. Logging Into the System
[p1122] 1.1 Launch the System
[p1123] Open a compatible web browser and navigate to the Lumina system website.
[p1124] 1.2 Microsoft 365 Login
[p1125] On the login page, select Sign in with Microsoft.
[p1126] 1.3 Enter Credentials
[p1127] Enter the user's STI Microsoft 365 account credentials and complete the required authentication process.
[p1129] 1.4 Role-Based Access
[p1130] Patrons start Pending at O365 sign-in and complete Student/Faculty, contacts and address (program for students only). "Edit Info" works until Librarian/Super Administrator approval as Active; then the role-based dashboard opens and details are read-only.
[p1131] 2. User Roles and Features (Patron, Library Staff, Librarian, Super Administrator)
[p1132] A. Patrons
[p1133] Patrons (students and faculty) use Lumina to search for books, make reservations, monitor borrowed books, and view their library information.
[p1134] Key Features
[p1135] View the Patron Dashboard.
[p1136] Search and browse available books.
[p1137] View book details.
[p1138] Reserve available books or join a waitlist.
[p1139] Track loan return deadlines and due soon reminders.
[p1140] View active borrows and unpaid fines.
[p1141] View and cancel reservations.
[p1142] View, export (Excel), and print borrowing history; view My Attendance.
[p1143] Access the digital library card.
[p1144] Export the library card.
[p1145] View frequently asked questions.
[p1146] View read-only profile details and manage profile photo.
[p1148] How To:
[p1149] Search for a Book:
[p1150] Open Catalog (/student-catalog) and enter title, author, or ISBN, optionally using category, availability, or sort filters.
[p1151] Select the desired book.
[p1152] Review the book details and availability.
[p1153] Reserve a Book:
[p1154] Open Catalog (/student-catalog).
[p1155] Select a book.
[p1156] Click "Reserve for Pickup" (or "Join Waitlist" for unavailable titles). The reservation is placed immediately upon click with a toast notification.
[p1157] View Active Borrowed Books:
[p1158] Open the Patron Dashboard.
[p1159] Locate the Current Borrows section.
[p1160] Review currently borrowed books, due dates, and returned books with unpaid fines.
[p1161] View Borrowing History:
[p1162] Navigate to My Borrowing (/history).
[p1163] Filter by All, Active, Overdue, Returned, or Settlements to review loans and penalties, or export Excel/print.
[p1165] B. Library Staff, Librarian, and Super Administrator
[p1166] Library personnel and administrators manage library resources according to assigned roles: Active Library Staff use only Super Administrator-granted Inventory (view/QR print), Circulation Desk/Borrowing Logs, and Attendance Logs permissions. Report Builder access covers only permitted Borrowing/Attendance datasets. Librarians manage inventory, circulation, fines, analytics, users (excluding Super Administrators and edits to other Librarians), policies, and Audit Logs excluding Super Administrator actions. Super Administrators retain full administration and lifecycle tools.
[p1167] Key Features
[p1168] Manage library books and assets.
[p1169] Add and edit book records.
[p1170] Monitor book statuses.
[p1171] Generate and print QR codes.
[p1172] Process book checkouts.
[p1173] Process book returns and settle overdue fines.
[p1174] Scan QR codes.
[p1175] Manage reservations.
[p1176] Monitor borrowing logs, attendance logs, analytics, Report Builder, and audit logs.
[p1177] Manage users.
[p1178] Configure System Policies (including fine rates and dashboard FAQs).
[p1179] Manage book categories and programs.
[p1180] Manage announcements.
[p1182] How To:
[p1183] Add a Book:
[p1184] As a Librarian or Super Administrator, open Inventory (/inventory).
[p1185] Select "Add Book" (/inventory/add).
[p1186] Enter the required book information.
[p1187] Use the automated ISBN lookup bar or enter book details, then click "Save to Catalog".
[p1188] Edit a Book:
[p1189] As a Librarian or Super Administrator, open Inventory (/inventory).
[p1190] Select the desired book or asset.
[p1191] Open the "Book information" tab and click "Edit book information".
[p1192] Update the required information.
[p1193] Click "Save Changes".
[p1194] Generate or Print a QR Code:
[p1195] Open the book in Inventory (/inventory) under "Copies & acquisition".
[p1196] Click "Print QR" on a copy row (under "Copy actions" for managers) or "Print all QR".
[p1197] Review the generated QR code.
[p1198] In the QR label dialog, click "Print Label" for one copy or "Print Labels" for multiple copies.
[p1200] Circulation Desk Functions
[p1201] The Circulation Desk is used by authorized library personnel to process book borrowing and returning transactions.
[p1202] Navigate to Circulation Desk (/circulation).
[p1203] Select Checkout.
[p1204] Use a handheld scanner, type the ID, or click "Start camera" (optional).
[p1205] Step 1 (Scan library card): Scan or type the card or Patron ID and click "Process". For overdue/lost-item or unpaid-fine blocks, a Librarian or Super Administrator may click "Override" and enter a 10?300 character reason.
[p1206] Step 2 (Scan item): Scan or type the Item QR code/accession number and click "Verify".
[p1207] Step 3 (Review): Review the transaction details and click "Confirm Checkout" to finalize the loan.
[p1208] B. Returning a Book
[p1209] Navigate to the Circulation Desk.
[p1210] Select Return.
[p1211] Use a handheld scanner, type the ID, or click "Start camera" (optional).
[p1212] Step 1 (Scan item): Scan or type the Item QR code/accession number and click "Process".
[p1213] Step 2 (Review Return): Review and click "Confirm Return". If overdue, record in-person payment with "Mark as Paid" or condone with "Mark as Condoned" (remarks: at least 5 characters). "Return Only (Pay Later)" leaves the fine Receivable.
[p1214] C. Resetting the Scanner
[p1215] If a scanning transaction needs to be cleared, click "Start over", or use "Stop camera" and "Switch camera" while the camera is active.
[p1216] 4. Managing Inventory
[p1217] The inventory management functions allow authorized library personnel to monitor and maintain library book records.
[p1219] Key Functions
[p1220] Add new library assets.
[p1221] Edit existing asset information.
[p1222] Monitor book status.
[p1223] Assign book categories.
[p1224] Generate QR codes.
[p1225] Update inventory, copy acquisition/disposal, and run Batch Operations.
[p1227] How To:
[p1228] Open Inventory (/inventory). Librarians and Super Administrators can update records; Active Library Staff with Inventory permission can only view records and print QR labels.
[p1229] Select the appropriate inventory function.
[p1230] Search for the required book or asset.
[p1231] Add or update the necessary information.
[p1232] Save the changes.
[p1233] 5. Managing Reservations
[p1234] Reservations are automatic (Ready for pickup or waitlisted); staff monitor queues and fulfill holds at checkout.
[p1236] How To:
[p1237] Access the appropriate reservation or circulation section.
[p1238] Review the list of active reservations.
[p1239] Check the Patron's reservation information.
[p1240] Verify the corresponding book.
[p1241] Monitor reservation queues within the Inventory book detail page ("Copies & acquisition" tab) and fulfill ready holds at the Circulation Desk during checkout.
[p1243] 6. My Borrowing and Borrowing Logs
[p1244] My Borrowing shows personal loans and penalties; Borrowing Logs lets authorized staff return items and settle fines.
[p1245] Patron
[p1246] Patrons can open My Borrowing (/history), use All/Active/Overdue/Returned/Settlements tabs, review Penalty, and choose Export (.xlsx) or Print. Settlements can be filtered by Paid or Condoned.
[p1247] Library Personnel
[p1248] Authorized staff open Borrowing Logs (/history?view=logs), click "Return / Settle" (overdue) or "Settle" (returned unpaid), and choose "Mark as Paid" (in person), "Mark as Condoned" (Remarks, 5+ chars), or "Return Only (Pay Later)" (Receivable). For custom reports, open Report Builder (/analytics/reports), set Report title, From/To dates, and up to 8 sections (Dataset, Metric, filters, Group by, Display), then click Print / Save PDF, Download Excel, or Download CSV (selected section only); Active Library Staff see only permitted attendance/borrowing datasets.
[p1249] 7. User Directory
[p1250] The User Directory allows authorized library personnel to manage registered users.
[p1253] Key Functions
[p1254] View accounts by role; Librarians cannot see Super Administrator accounts or edit other Librarians.
[p1255] Search by name, email, or student ID.
[p1256] Open a user profile to review details and borrowing history. For a completed Pending profile, click "Verify & Approve", check the institutional ID, then "Confirm & Activate".
[p1257] Librarians can edit Patron/Library Staff details and set Active/Pending/Inactive. Super Administrators manage all roles and Active/Pending/Inactive/Suspended/Archived statuses, grant Library Staff permissions, and transfer ownership.
[p1258] 8. System Policies
[p1259] System Policies (/policies) allows Librarians and Super Administrators to configure library rules and information; lifecycle tools are Super Administrator-only.
[p1261] Available Policies
[p1262] Borrowing window.
[p1263] Maximum books allowed per Patron.
[p1264] Loan period (default 14 days), maximum books (5), pickup window (3 days), and overdue fine rate (PHP 5/calendar day).
[p1265] Reservation shelf life.
[p1266] Maximum active holds (default 3).
[p1267] Academic programs (students only).
[p1268] Book categories.
[p1269] Announcements (Patrons & Library Staff or all users), dashboard FAQs, and Super Administrator lifecycle tools (annual reset of all Patrons including faculty, archiving records older than one year after Excel backup, maintenance, and test email).
[p1271] How To:
[p1272] Navigate to System Policies (/policies).
[p1273] Select the policy or configuration that needs to be updated.
[p1274] Enter the required information.
[p1275] Review the changes.
[p1276] Click "Review Changes" on the floating bar, enter a mandatory Audit Protocol Reason (minimum 10 characters), and click "Confirm & Commit".
[p1277] 9. Common Functions
[p1278] A. Reporting a Missing Book
[p1279] Contact library personnel about a missing book.
[p1280] B. Viewing the Library Card
[p1281] Open the Patron Dashboard.
[p1282] Locate the Library Card section.
[p1283] View the digital library card.
[p1284] Use "Show card back" or "Show card front" to inspect the card, click its QR code to enlarge it, and use Export to save a PNG image.
[p1285] C. Viewing FAQs
[p1286] Open the Patron Dashboard.
[p1287] Locate the inline Support & FAQs section on the dashboard.
[p1288] Select the question related to the user's concern.
[p1289] Review the provided information.
[p1291] 10. Updating Personal Information
[p1292] Users can review personal information and update their profile photo.
[p1293] Navigate to My Profile (/profile).
[p1294] Review the read-only details and Account Access note; academic program appears for student Patrons only.
[p1295] Click "Click to update photo", select an image, and adjust its crop and zoom. Use "Remove photo" to remove an existing image. Pending users can use "Edit Info" on the approval screen to revise onboarding details.
[p1296] For photo uploads or replacements, click "Save Changes" in the crop dialog; removal needs no separate save.
[p1297] 11. Logging Out
[p1298] To securely exit Lumina:
[p1299] Click the user's profile icon.
[p1300] Select "Log out", then click "Log out" in the confirmation dialog.
[p1301] The system will end the current session.
[p1302] Users should always log out after using Lumina on shared or public computers.
[p1303] 12. Troubleshooting and Support
[p1304][tbl] Issue
[p1305][tbl] Suggested Solution
[p1306][tbl] Unable to log in
[p1307][tbl] Check Microsoft O365 credentials. At "Activation Required", present a valid school ID at the library desk for Librarian/Super Administrator approval; suspended accounts require Super Administrator assistance.
[p1308][tbl] Cannot access a feature
[p1309][tbl] Check account status and role; Library Staff need an Active account and the relevant Super Administrator permission.
[p1310][tbl] Book cannot be reserved
[p1311][tbl] Check the active hold limit (default 3); if no copy is free, use "Join Waitlist".
[p1312][tbl] QR code cannot be scanned
[p1313][tbl] Check camera alignment and access; if needed, use a handheld scanner or typed copy/card number (student ID also works for checkout and attendance).
[p1314][tbl] Book information is incorrect
[p1315][tbl] Report the issue to authorized library personnel.
[p1316][tbl] Borrowing or returning transaction cannot be completed
[p1317][tbl] Verify card/copy details and account status. Overdue/lost items or unpaid fines block borrowing; a Librarian or Super Administrator may override with a recorded reason. Self-checkout is blocked; returns need only the copy.
[p1318][tbl] System is not loading
[p1319][tbl] Check the internet connection and refresh the browser.
[p1321] For unresolved issues, users should contact the authorized library personnel or system administrator.
